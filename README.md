# ⚡ Loss Lens

**An AI copilot that shows electricity distribution companies where their energy is being lost or stolen — and which customers are being unfairly overbilled — so honest customers stop paying for everyone else's losses.**

Built for the **Global Energy Hackathon 2026** (Anneru Solutions) · Track: Digital Solutions, Apps & AI/ML Tools · Pillar: **Affordability**

---

## The problem

In many countries, distribution companies lose 15–30% of the electricity they buy to theft (hooks / *kunda*, bypassed and tampered meters) and to faulty metering. Those losses don't disappear: they are recovered through tariffs. **Honest customers pay for stolen power.** At the same time, poor estimated billing overcharges vulnerable households.

Utilities already collect the data that reveals all of this — smart-meter (AMI) reads, meter tamper events, feeder input energy and billing. But it sits in separate systems, and finding answers takes analysts days of SQL.

## What Loss Lens does

| Screen | What a manager gets |
|---|---|
| **Overview** | Every feeder ranked by loss above normal technical losses, with a daily "energy sent in vs energy metered" drill-down |
| **Ask** | Plain-English questions → answer, chart, and the SQL behind it |
| **Inspection list** | Meters ranked by risk with plain-English reasons, a consumption chart with tamper events, and a field work order (English + Urdu when AI is on) |
| **Fair billing** | Customers billed far above what their meter recorded, and the refund due |
| **Accuracy** | Detection scored against a known answer key |
| **Audit log** | Every question, query and outcome — including blocked ones |

## Results on the demo dataset

Synthetic utility "Riverbend Power": 30 feeders, 6,000 smart meters, 92 days.

- Overall loss **12.9%**; five hook-theft feeders run at **25–32%**
- **823 MWh** lost above technical losses in 3 months ≈ **PKR 45 million**
- Recovering it is worth about **6% of all bills** — money that could come off honest customers' tariffs
- **284 meters** prioritised for inspection — **100% precision, 99% recall** against the answer key
- **5 / 5** hook-theft feeders ranked top 5; **72 / 72** overbilled customers found (PKR 1.3 M refund due)

> Honest note: the rules score this cleanly because the data is synthetic. Real AMI data is noisier — which is why Loss Lens always shows its reasons and SQL, and a human approves every inspection.

## How it works

```
Question ─► AI (or offline example matcher) ─► SQL
                                              │
                               Guardrails: one read-only SELECT,
                               allow-listed tables, no file/system
                               functions, row limit
                                              │
                      DuckDB (opened read-only) ─► result ─► chart + plain-English answer
                                              │
                                         Audit log
```

- **Semantic layer** — business views (`v_feeder_loss_monthly`, `v_inspection_list`, `v_billing_mismatch` …), plain-English utility rules, and 13 worked examples. The same approach raised my previous utility copilot from 12/20 to 23/23 accuracy.
- **Self-correction** — if AI-written SQL fails, the error goes back to the model for one retry.
- **Guardrails** — 8/8 attack attempts blocked in the built-in test (DELETE, DROP, multi-statement injection, file reads, reading API keys, ATTACH, table functions). The database is also opened read-only.
- **Model-agnostic** — Claude, OpenAI, Gemini, or a fully on-premise local model via Ollama. Utilities can keep customer data inside their own network.
- **Works offline** — with no AI key, every screen still works and Ask answers questions similar to the worked examples.

## Run it

```powershell
git clone <this repo> loss-lens
cd loss-lens
python -m venv .venv
.\.venv\Scripts\Activate.ps1          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python data\generate.py               # builds the synthetic dataset (~2 seconds)
copy .env.example .env                # optional: add ONE AI key
streamlit run app\app.py
```

## Path to deployment (6–18 months)

| Phase | Months | What happens |
|---|---|---|
| Pilot | 0–6 | One distribution circle; read-only replica of CIS, AMI and billing; on-premise model; crews verify the top 100 suspects a month |
| Prove | 6–12 | Measure recovered kWh, refunds issued and complaints resolved; tune rules on real inspection outcomes |
| Scale | 12–18 | All circles; confirmed cases become training labels; loss and overbilling reports for the regulator |

## Data

All data is synthetic, generated by `data/generate.py`. No real customer, meter or utility data is used. See `data/README.md` for tables, views and the planted patterns.
